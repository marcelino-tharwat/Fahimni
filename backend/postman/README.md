# Postman — STORY-45 local testing

Local-only Postman assets for testing `POST /api/quizzes/generate` against the
seeded **General Secondary Education** dataset.

## Files

| File | Tracked? | Purpose |
|---|---|---|
| `Fahimni_Local.postman_environment.template.json` | ✅ tracked | Safe template — empty credentials/IDs/tokens. Copy/import this if you don't run the seed. |
| `Fahimni_Local.postman_environment.json` | 🚫 git-ignored | **Generated by the seed.** Populated with local IDs + the local password. Import this for ready-to-run testing. |
| `story45-seed-manifest.local.json` | 🚫 git-ignored | **Generated by the seed.** IDs only, no secrets. |

> The populated env and manifest are produced by the seed and are never committed.
> The local password lives **only** inside the generated populated env (and can be
> overridden with the `SEED_LOCAL_PASSWORD` env var). It is never placed in any
> tracked file.

## Generate / refresh the local data

```powershell
# from backend/ (Windows PowerShell)
npm run db:seed                 # relational data + manifest + populated env (idempotent)
npm run db:seed:verify          # read-only assertions on the seeded DB

# AI-ready indexing of the successful chapter (needs GEMINI_API_KEY, uses quota):
$env:SEED_AI_READY="true"; npm run db:seed; Remove-Item Env:SEED_AI_READY
```

```bash
# bash equivalent
npm run db:seed
SEED_AI_READY=true npm run db:seed
```

The seed is **idempotent** and **local-only** (it refuses to run against a
non-local / production database).

## How to test in Postman

1. Start the backend: `npm run dev` (listens on `http://localhost:3000`).
2. Import `Fahimni_Local.postman_environment.json` (populated) as the active environment.
3. Auth is an **HttpOnly `access_token` cookie** — there is no bearer token in the
   response body. Postman's Cookie Jar reuses it automatically, so **log in with the
   right role immediately before the requests that need it**:
   - Teacher 1 (`{{teacherEmail}}`) for success / 404 / unindexed / cross-teacher tests.
   - Student (`{{studentEmail}}`) for the 403 test.
   - Teacher 2 (`{{otherTeacherEmail}}`) only if you test his own content.
   To switch roles cleanly, clear cookies for `localhost` (or use Postman's "Clear
   cookies") then log in as the next role.

## Run order (direct STORY-45 journey)

| # | Request | Expected |
|---|---|---|
| 1 | `GET /health` | 200 |
| 2 | `POST /api/v1/auth/login` (teacher1) | 200 (sets cookie) |
| 3 | `POST /api/quizzes/generate` `{ chapterId, questionCount:5, types:[MCQ,TF,ESSAY], difficulty, topicFocus }` | **201 DRAFT** |
| 4 | `POST /api/quizzes/generate` `{ lessonIds:[lessonId1,lessonId2], ... }` | **201 DRAFT** |
| 5 | login student → generate | **403** |
| 6 | generate with no login | **401** |
| 7 | generate invalid body (`questionCount:0`) | **400** |
| 8 | generate `chapterId={{missingUuid}}` | **404** |
| 9 | generate `chapterId={{unindexedChapterId}}` | **422** (not indexed) |
| 10 | generate `chapterId={{otherTeacherChapterId}}` (as teacher1) | **403/404** (ownership) |

## Verify RAG readiness / DRAFT

- RAG ready: `GET /api/ai/status/{{lessonId1}}` → `status: "ready"`, `chunkCount > 0`.
- DRAFT row: the generate response returns `status: "DRAFT"`; drafts are excluded
  from student-facing chapter quiz listings until published.

## No-secret policy

Never commit the populated env, the manifest, tokens, the local password, or the
Gemini API key. Only the template and this README are tracked.
